## Gemma 4の比較（合成会議、実機）

2026-09-24に同じ6発言、8,192トークン設定、JSON Schemaで比較した。これはモデル選定の予備測定であり、長時間会議の品質や停止後の所要時間を保証しない。

| モデル | 所要時間 | GPU配置 | 内容 |
| --- | ---: | --- | --- |
| `qwen3.5:9b` | 未計測 | 62% GPU / 38% CPU | 担当者IDの整合性検証に2回失敗 |
| `qwen3.5:4b` | 21秒 | 未計測 | JSONは有効。担当作業をTODOに入れられなかった |
| `gemma4:e4b-it-qat` | 46秒 | 100% GPU | JSONは有効。概要が定型文で、担当作業をTODOに入れられなかった |
| `gemma4:12b-it-qat` | 163秒 | 60% GPU / 40% CPU | JSONは有効。決定、TODO、未決事項を区別できた |

Gemma 4の2モデルはOllamaへ追加済みだが、CordScribeの稼働モデル設定は`qwen3.5:9b`のまま。12Bは6GB GPUに全量収まらず、3時間会議の多数の抽出に使うには遅い。E4Bは全量載るが、このサンプルの要約品質では切り替えを決められない。会議中に別サービスが異なるOllamaモデルをロードした場合、現状のBotは自分の設定モデルだけを解放するため、GPU競合の実機確認も必要。

E4Bに約4,839文字の日本語合成入力と実装のJSON Schemaを与えたところ、入力は2,334トークンだった（設定上限8,192）。これは1チャンクの目安を確かめた値で、話者数、語彙、統合結果によるトークン増加まで保証するものではない。

- 無言・環境音だけの区間がVADで無視され、通常の短い日本語発話は残ることを実VCで確認する。音声に似た雑音や別人の声は残り得るため、再試験結果で追加調整を判断する。
- 音楽Bot・読み上げBotの音声ストリームを記録しないことと、参加者マイクに回り込んだ音の扱いを実VCで確認する。
- 退出・再入室とVC再接続を実機で確認する。
- 2〜8人相当の同時発話と既存チャットBotの同時利用を確認する。
- 任意の通常テキストチャンネルから開始し、会議を開始したチャンネルへの案内・Markdown添付、ほかのチャンネルからの後続操作の拒否を確認する。
